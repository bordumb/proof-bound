## Why a new corpus is required

The original twenty cases were enough to extract common evidence meaning and
falsify several unsafe normalizations. They are not enough to close the final
Q1 boundary. Most language cases retain registration but not the matching
observation, cache execution, portable receipt, and effective policy. The one
portable fixture has a complete release boundary but deliberately little
language-specific evidence.

Adding an admission trace to that corpus now would risk restating expected
status labels. Calling a list of declared inputs a complete cache closure would
be equally circular. The completion corpus therefore captures three whole
verticals—Python, TypeScript, and Rust—from registration through fresh
execution, reuse, release, and independent verification.

## Execution order

1. Create a detached clean worktree at the registered subject commit.
2. Record the platform and exact tool identities before evidence execution.
3. For each project, run a fresh check of the registered claims.
4. Run an unchanged second check and capture any reused prior receipt.
5. Build a portable release and retain only canonical semantic artifacts, not
   copied verifier executables or dependency directories.
6. Resolve each selected claim to its complete registration, evidence,
   assumptions, premises, policies, closures, observations, and receipts.
7. Apply every registered artifact and invalidation attack in a separate
   disposable copy. Never alter the frozen subject or reuse attack state.
8. Only after capture is frozen, implement the typed derivation trace and the
   independent Rust/Python comparisons.
9. Publish a new matrix revision. Do not edit revision 3 or the earlier failed
   Q1 result.

## Stored artifacts

The experiment should commit bounded semantic records and an index of their
identities. It should not commit `.venv`, `node_modules`, Cargo targets,
Proofbound caches, native binaries, or complete release directories. A minimal
capture contains:

- check and cache-origin summaries;
- compiled receipt, release envelope, and TCB ledger;
- evidence records cited by selected claims;
- exact source-manifest identities;
- tool/backend identities;
- mutation outcomes for the preregistered attacks; and
- canonical Rust and Python trace outputs.

This split keeps the repository reviewable while preserving every semantic
input needed to reproduce the research claim.

## Stop conditions

Stop and keep the affected row partial if:

- a tool required by a selected route is unavailable or not exactly
  identifiable;
- a cache dependency can change without invalidating or rejecting reuse;
- the independent checker needs the originating Python, Node, Rust, Lean, or
  Kani toolchain;
- a derivation rule consumes a reported status or adapter-authored admission
  Boolean;
- an artifact role cannot be reconstructed without ambient path inference; or
- either implementation needs a concrete backend-name branch in generic
  derivation.

The Go implementation remains a future holdout. It is intentionally excluded
from this completion corpus and may not start until the IR is frozen.
